Architecture

Columbus Housing Pipeline

How sales and market data for Franklin, Delaware and Licking counties get from public sources into SQL Server, and from there into the trend report.

Public source, fetched by code Manual file, you obtain it Python code Table View, rebuilt on every connect

Run order

  1. python run.py all --since <date> --file <redfin download> weekly, Monday morning. Runs the Franklin loader, then Redfin, then the report. Without --file or --url, Redfin is skipped. Don't miss a week: Franklin pages drop off after about 30 weeks.
  2. python run.py county-file --county Delaware --file <file> whenever a county file arrives. Same for Licking. Not part of all.
  3. python run.py zillow monthly, after Zillow updates on the 16th. Skips files unchanged since the last load. Not part of all.
  4. python run.py reparse after a parser fix. Re-reads every saved Franklin page from raw_page, no network.
  5. python run.py report --export out/ any time, for the summary and a CSV of each view, plus ATTRIBUTION.txt for Zillow.

Each connect creates the database and any missing tables, then rebuilds the views. python pipeline/db.py does only that and prints row counts, as a connection check. python -m pytest -q runs the tests against a separate columbus_housing_test database.

Components

FileJob
run.pyCommand line: auditor, reparse, county-file, redfin, zillow, report, all. Prints the report.
pipeline/auditor.pyFinds Franklin weekly sales report pages, saves each page to raw_page before parsing, parses the sales tables, records the county's own count for validation.
pipeline/county_file.pyReads a Delaware or Licking export (CSV, TSV, .xls, .xlsx). Matches columns by header name, keeps residential rows, pulls ZIP from the address if needed.
pipeline/redfin.pyReads a downloaded Redfin weekly file in 200k-row chunks and keeps the Columbus metro row plus the three county rows.
pipeline/zillow.pyDownloads Zillow's county and ZIP ZHVI CSVs (or reads --file), keeps the three counties and their ZIPs, replaces that kind's rows.
pipeline/http.pyAll web requests: honors robots.txt, waits 2 seconds between calls, retries with backoff.
pipeline/db.pySQL Server connection (Windows auth), schema setup, and the write helpers.
sql/schema.sqlTables. Created only if missing.
sql/views.sqlViews. Rebuilt on every connect.
tests/Parser tests on hand-made fixtures, plus database tests on a throwaway database.

What makes it safe to rerun

  • SalesA sale is keyed on county, parcel, date and price. Loading the same report or file twice adds nothing.
  • ReportsFranklin pages already loaded and saved are skipped unless you pass --refetch. Raw pages are stored once per distinct content.
  • FailuresEach load commits once at the end. A crash midway leaves the database as it was, except the raw page, which is saved first on purpose.
  • RedfinThe table is replaced on every load, since Redfin revises past weeks.
  • ZillowEach kind (county, ZIP) is replaced wholesale, and skipped when the file's Last-Modified hasn't changed.

Known gaps

  • Data lossA missed weekly run loses that Franklin week for good once the county drops it (~30 weeks). Franklin YoY needs a full year of captured weeks.
  • Alertsrun.py all logs a Redfin failure but still exits successfully, and skips Redfin silently without --file, so a scheduled run can miss it quietly.
  • VerifyTests use hand-made fixtures, not real downloads. Check v_report_validation after the first Franklin backfill.
  • SchemaChanges to an existing table are not applied. They need a migration script.
  • ManualRedfin's new Data Center has no stable file URL, so each week's file is a manual download.
  • Mix shiftNo square footage, beds or year built, so medians move with mix. Treat moves under ~3% as noise.
  • CoverageDelaware and Licking are only as current as your last file. Fairfield, Union, Madison and Pickaway are not included.
  • AttributionZillow and Redfin must be credited wherever their data is shown.
